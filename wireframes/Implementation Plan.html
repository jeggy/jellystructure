Jellystructure — Build Plan

End-to-end instructions to implement the system: shared Kotlin domain, Kotlin/Native backend, Kotlin/Wasm DOM frontend, Jellyfin sign-in, and the Docker deployment — broken into six buildable phases, each with concrete tasks and exit criteria.

Kotlin Multiplatform Native backend · Ktor CIO Wasm frontend · real DOM Jellyfin auth (seerr-style) Docker Compose

Read this alongside the Requirements & Phases doc (it owns the numbered FR/NFR IDs) and the wireframes (they own the screens). This doc owns how we build it.

0 · Architecture at a glance

One Gradle multiplatform repo, three Kotlin modules plus a Tailwind toolchain. The shared module is the trick that makes the app feel coherent: DTOs and the cascade-resolution logic live there, compiled into both the Native backend and the Wasm frontend — so the live resolver preview in the browser runs the exact same code the backend uses to make decisions.

Native gotchas to design around up front. (1) No JVM crypto — generate session tokens from /dev/urandom, not java.security. (2) No ktor-server-auth-jwt on Native — use opaque sessions. 1 · The auth model (Jellyseerr-style)

There is no Jellystructure password. The user signs in with Jellyfin credentials; we verify them against the Jellyfin server and issue our own session. This satisfies FR-AUTH1–5.

Login sequence

  1. Browser POSTs { username, password } to POST /api/auth/login.
  2. Backend calls Jellyfin POST {jellyfin_url}/Users/AuthenticateByName with an auth header and body { "Username", "Pw" }.
  3. Jellyfin returns { User { Id, Name, Policy.IsAdministrator }, AccessToken, ServerId }.
  4. Reject if IsAdministrator == false (FR-AUTH2). Otherwise mint an opaque session token, store (token → userId, jellyfinUserAccessToken, expiresAt) in SQLite.
  5. Set cookie js_session=<token>; HttpOnly; SameSite=Lax; Path=/ (add Secure behind TLS). Return the safe user profile (no token) as JSON.
  6. A Ktor plugin validates the cookie on every /api/** route and on the WebSocket upgrade; missing/expired → 401 (FR-AUTH3). The password is never persisted (FR-AUTH1).
// Jellyfin auth header — same scheme seerr uses
Authorization: MediaBrowser Client="Jellystructure", Device="Server",
              DeviceId="<stable-uuid>", Version="0.1.0"
// after login, machine calls add Token="<accessToken>"

// backend route
post("/api/auth/login") {
    val creds = call.receive<LoginRequest>()
    val res = jellyfin.authenticateByName(creds.username, creds.password)
    if (!res.user.policy.isAdministrator) return@post call.respond(Forbidden)
    val token = sessions.create(res.user.id, res.accessToken)
    call.response.cookies.append(sessionCookie(token))
    call.respond(UserProfile.from(res.user))
}
Two Jellyfin tokens, on purpose (FR-AUTH5). The user access token from login authenticates UI session ownership. Background jobs (scan, refresh) use the separate machine jellyfin_token from Settings so they run with nobody logged in. Never use a user's login token for scheduled work — it dies when they log out.

Bootstrap

Before jellyfin_url is set there's no one to authenticate against, so the very first run shows a one-time setup screen (enter Jellyfin URL + TMDB key, write config.toml) that is open only until config exists; afterwards it 404s and login is required.

2 · Shared API contract

Define DTOs once in shared/model; both sides import them, so the wire format can't drift. A representative slice:

@Serializable data class MediaItem(
  val id: String, val title: String, val year: Int?,
  val kind: MediaKind, val path: String,
  val tmdbId: Int?, val originalLanguage: String?,
  val tags: List<String>,
  val tracks: List<Track>,
  val artwork: ArtworkStatus,
  val cascadeOverride: List<String>?   // null = inherit global
)
@Serializable data class Track(
  val index: String,            // "0:a:1"
  val kind: TrackKind, val codec: String,
  val language: String?,        // null ⇒ shows up in Triage
  val title: String?, val default: Boolean, val forced: Boolean
)
// the same resolver runs on backend AND in the browser preview
object CascadeResolver {
  fun resolve(available: List<String>, rule: Cascade, originalLang: String?): String
}

WebSocket frames are a sealed JobEvent hierarchy (Started, FileProgress, FileDone, Error, Finished) serialized with a class discriminator — the frontend exhaustively whens over them.

3 · Delivery phases

Six phases. Each ends in something you can run and verify. Lanes: SHARED BACKEND FRONTEND OPS.

P0Scaffolding & deployable skeleton~1 week

Objective

A container that builds and serves a "hello" page, so the whole toolchain (KMP → native binary + wasm bundle → Docker) is proven before any features.

Ops
  • Repo, version catalog, Gradle KMP with linuxX64/linuxArm64 + wasmJs targets.
  • Dockerfile: multi-stage — build stage runs Gradle, runtime stage is slim Debian with ffmpeg + mkvtoolnix installed, runs as non-root 1000:1000.
  • docker-compose.yml: media volume (:rw), config volume (:rw), shared network with Jellyfin, restart: unless-stopped (NFR-8).
Back
  • Ktor CIO embeddedServer; GET /healthz; serve the wasm bundle + static assets from one port.
Front
  • Minimal wasmJs main() that writes a node into document.body; Tailwind build wired (styles.css → served).
Exit criteriadocker compose up serves a Tailwind-styled page rendered by Kotlin/Wasm; /healthz returns 200; ffmpeg/ffprobe/mkvpropedit resolve on PATH inside the container.
P1Config, DB, auth & library mapping~2–3 weeks

Objective

Persistent typed config, the local DB, full Jellyfin sign-in with sessions gating the API, and a library-mapping UI so the operator can wire each Jellyfin library to a local path (or skip it). (FR-C1–6, FR-AUTH1–5)

Shared
  • AppConfig, LoginRequest, UserProfile DTOs.
  • LibraryMapping DTO: jellyfinId, name, collectionType, localPath, skip.
  • JellyfinLibrary DTO: the raw response shape from GET /Library/VirtualFolders.
Back
  • ktoml load/save of /config/config.toml; defaults on first run; atomic write (temp + rename via Okio). Config schema: [api_keys], [language_rules], [behavior], [[libraries]] array (replaces flat [paths]).
  • SQLDelight schema: session, setting_audit. Native SQLite driver; migrations.
  • JellyfinClient.authenticateByName(); SessionService (urandom token, TTL, revoke); AuthPlugin intercepting /api/** + WS upgrade.
  • Routes: /api/auth/login, /logout, /me; /api/config GET/PUT; /api/setup (open until config exists).
  • POST /api/connections/test → pings TMDB + Jellyfin, returns literal status (FR-C4).
  • GET /api/jellyfin/libraries → proxies GET /Library/VirtualFolders from the configured Jellyfin instance; returns List<JellyfinLibrary> (FR-C5). Requires a valid session + configured Jellyfin URL.
  • PUT /api/config/libraries → accepts List<LibraryMapping> and merges into the [[libraries]] TOML array atomically (FR-C6).
Front
  • Router + app shell (sidebar from wireframes); auth guard redirecting to /login.
  • Login screen; Settings screen (sectioned form ↔ live TOML mirror) bound to /api/config.
  • Library Mapping section in Settings: a "Fetch Libraries" button calls /api/jellyfin/libraries (also called automatically after a successful connection test); renders one row per library with a local-path text input and a "Skip" toggle. Save button calls PUT /api/config/libraries (FR-C5–6).
Exit criteriaAdmin logs in with Jellyfin creds and reaches Settings; a non-admin is refused; editing a field persists to config.toml and survives container restart; hitting any API without the cookie returns 401. After a successful connection test the Settings page shows the Jellyfin library list; marking a library as skip and saving is reflected in config.toml.
P2Jellyfin-driven discovery, probe & the media model~3 weeks

Objective

Enumerate items from Jellyfin, verify on disk, read real track data, match against TMDB, and render Library + Media Detail. No filesystem walk. (FR-M1–2, FR-M5, FR-T1, FR-J1, parts of FR-A/M)

Shared
  • MediaItem, Track, TrackKind, MediaKind, LanguageSampleResult (Uniform(langs) / Mixed).
Back
  • JellyfinClient.getItems() — GET /Items?IncludeItemTypes=Movie,Series&Recursive=true&Fields=Path,ProviderIds,ProductionYear using the machine token; deserialise into JellyfinItem(id, name, year, path, tmdbId?, type). Filter out anything that isn't Movie or Series (FR-M1, FR-J1).
  • Movies: verify the file at item.path exists on disk; run ffprobe to get tracks (FR-T1); use Jellyfin's tmdbId if present, otherwise search TMDB by name + year (FR-M2).
  • TV Series: verify the series directory at item.path exists; collect all episode files recursively; pick up to 5 samples spread across the collection; run ffprobe on each sample (FR-T1); compare audio language sets — if all samples agree produce LanguageSampleResult.Uniform(langs), else Mixed (FR-M5). Use Jellyfin's tmdbId for TMDB fetch; mark Mixed series with issueKind = LANGUAGE_MIX and skip NFO/artwork writes until resolved.
  • TmdbClient (search by name+year fallback + details + original_language); resilient to rate limits.
  • Persist scanned items + tracks + issues; each item emits JobEvent.ItemScanned immediately (FR-U1); /api/media (list, filter, paginate), /api/media/{id}.
Front
  • Library poster grid: poster cards stream in via WebSocket as each item is processed. Language mix items show an orange warning badge distinct from the red untagged tracks badge.
  • Media Detail: show language sample results for TV series ("sampled 5 episodes — languages uniform: [fo, da]" or "language mix detected — unsupported"); track table shows sample tracks only.
Exit criteriaAll Movies and Series in the connected Jellyfin library appear in Jellystructure; opening a Movie shows TMDB fields and the real track list from ffprobe; a Series with uniform languages shows its resolved language; a mixed-language series shows a warning badge and no NFO is written.
P3NFO, artwork & cascade engine~3 weeks

Objective

Write the on-disk truth (NFO + images) and stand up the cascade resolver with its live preview. (FR-M2–4, FR-A1–3, FR-L1–5)

Shared
  • Cascade, CascadeResolver.resolve(...) (pure, fully unit-tested), NfoFields.
Back
  • kotlinx-io NFO writer for movie.nfo / tvshow.nfo (episode-level NFOs are out of scope), always emitting <lockdata>true</lockdata> (FR-M3); atomic write (temp + rename); preserve uid/gid & mode (FR-T4).
  • "Re-pull" merge that fills empty/unlocked fields without clobbering edits (FR-M4).
  • Artwork downloader (Ktor client, parallel) → poster.jpg/fanart.jpg/clearlogo.png; report present/missing (FR-A1–3).
  • Cascade endpoints: global rule in config; per-title override on the item; /api/cascade/resolve echoing the shared resolver for the preview.
Front
  • Cascade screen: drag-ordered list + fallback + live resolver (runs the shared resolver in-wasm — no round trip).
  • Artwork rail: fetch/upload/replace; NFO raw view.
Exit criteriaSaving a title writes a locked, well-formed NFO and images next to the media with ownership intact; the resolver preview and backend agree byte-for-byte on the chosen language.
P4Track editing, triage, jobs & live UI~3 weeks

Objective

Edit the containers themselves, work the triage queue, and stream everything live. (FR-T2–5, FR-R1–4, FR-J1–2, FR-U1–2)

Shared
  • JobEvent sealed hierarchy (Started, FileProgress, FileDone, ItemScanned(item: MediaItem), Finished); TrackPlan (before/after + chosen tool).
Back
  • Default/order via mkvpropedit (header-only) for MKV; ffmpeg -c copy remux fallback for MP4 / reorder / removal, flagged as slower (FR-T2–3).
  • Dry-run planner across many files: list affected + tool, write nothing (FR-T5).
  • Triage query: all untagged tracks + default≠cascade mismatches; assign-language writes back to the file (FR-R1–4).
  • Job runner with a worker queue; broadcast JobEvents over /api/ws; errors push the item to triage and continue (FR-U2).
  • Scanner calls store.updateOne(item) after each file and broadcasts JobEvent.ItemScanned(item) so the REST API and WebSocket both reflect in-progress state immediately (FR-M1, FR-U1).
  • Jellyfin refresh: POST /Items/{id}/Refresh (and /Library/Refresh bulk) using the machine token; surface 204 (FR-J1–2).
Front
  • Triage focus queue (keyboard assign, accept & advance).
  • Track-order before/after diff with exact command preview + Apply.
  • Activity console + ambient dock, both fed by one WS StateFlow (FR-U1).
  • Library subscribes to the WS during an active scan; on each ItemScanned event, appends or updates the item in the poster grid immediately — operator sees results accumulate without waiting for completion (FR-M1, FR-U1).
Exit criteriaApplying the cascade to a real MKV flips the default track in <100ms with no re-encode (verified by re-probe); a scan batch streams live progress and the Library poster grid populates item-by-item as each file finishes — no waiting for scan completion; a failed match lands in triage while the run continues; Jellyfin reflects the change with no manual refresh.
P5Automation, fixtures & test regime~2–3 weeks

Objective

Folder watching, the real-media test harness, and CI. (FR-U3, NFR-T1–4)

Back
  • Folder watcher → auto-process new files per rules (FR-U3); debounce partial copies.
  • Hardening: cancellation, retries, structured logs, graceful shutdown closing WS + DB.
Ops
  • Fixture builder: download Big Buck Bunny / Sintel / Tears of Steel, mux in alternate-language audio, set a wrong default — a genuinely broken library to repair (NFR-T2). Real containers, never renamed text files.
  • Playwright-in-Docker: log in, save config, run a reorder, assert the live UI updates; visual snapshots of key states (NFR-T1).
  • Post-run assertions via ffprobe that defaults/order actually changed; mock TMDB for determinism (NFR-T3); CI on every change (NFR-T4).
Exit criteriaFrom a freshly built broken fixture, CI logs in, runs the cascade, and ffprobe confirms every file's default now matches the rule — green on every push.

4 · Build order & dependencies

Strictly sequential at the seams: P0 proves the toolchain, P1 gives you auth + config that everything else assumes, P2 produces the data model the UI hangs on, P3 makes writes safe (NFO/lockdata) before P4 touches media bytes, and P5 automates + proves it. Within a phase, build SHARED first, then BACKEND, then FRONTEND against the live endpoints.

5 · Decisions closed

  • Undo / history depth — decided: lightweight audit row per write in the SQLite DB; surfaced in the History tab of Media Detail (GAP-1 in §6 below). No restorable diff store.
  • Session lifetime — decided: 7-day default, displayed on the login screen. No "remember me" toggle.
  • External-edit conflicts — decided: warn on next scan (show a "file changed" badge in Library). No automatic re-lock. Deferred to a future minor release.
  • Music & other providers — out of scope. Jellyfin library discovery (FR-C5) surfaces music/books/photos; the operator marks them "skip".
