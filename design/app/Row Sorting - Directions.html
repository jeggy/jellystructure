How a content row lines up

Every workbench row on the TV is ordered the same way today, and nothing in the editor says so: newest added first, then title, cut at 30. That is the right order for a row called Newly Added and an accidental one for a row called Danish drama. This round adds one section to the row editor — Order — with three automatic keys, a direction, and a fourth mode where you hand-pick the front of the row and let one of the automatic keys place everything behind it, so the row keeps working as it grows.

What exists today, from the code

One order, hard-coded

HomeFeedService sorts every filter row compareByDescending(recencyKey).thenBy(title) and takes ROW_ITEM_LIMIT = 30. RowConfig has no sort field at all.

See all already sorts

R187's browse page offers recency · title · year as a facet, client-side, over the full seed. The row and its See all page can therefore disagree about order — today they do, silently, whenever a viewer changes the facet.

Rows live in two places

The Home stack, and each collection's Custom row set (R59) — both are RowConfig verbatim, edited by the same modal. Whatever Order gets, both get for free; a Home row inherited into a collection is scoped, not re-sorted.

Confirmed 2026-09-17: newest first is the intended default. The brief says the default should stay added date (asc) “just like now”. What runs now is newest first (descending by added date). Every frame here keeps today's behaviour as the default and labels it Date added · newest first; if oldest first was genuinely meant, it is one flip of the direction control, not a different design.

Rules held on every frame

  • The server sorts; the TV renders. Order is a property of the row config, resolved in HomeFeedService — the constitution's render-never-compute rule. No client re-implements a comparator, and no new string reaches en/da/fo: the viewer sees an order, never a reason.
  • Hand-picks are a prefix, not a replacement. Whatever you pin comes first, in your order; everything else the filter matches follows under the automatic key you choose. A row that gains fifty titles next month still lines up.
  • The 30 cap becomes “the first 30 in this order”. Today the cap is invisible because it always cuts the oldest. Under Title A → Z it cuts at the letter D — the editor has to say so, and See all is where the rest lives.
  • System rows are not touched. Continue Watching is chronological by activity (R219), Newly Added is by definition newest first. Neither gets an Order section.
  • Hand-picks belong to the row, not to the collection. A pinned title outside the collection a row is rendered in simply doesn't appear there — nothing to configure twice.

Decided — 2026-09-17

The owner picked direction 2 · Arrange the row the same day; every lean below became the answer. Built into the row editor (app/ravilo-config.html → any workbench row → Order) and spec'd as 225 (config field, server resolver, editor) + R253 (See all opens in the row's order). Decision 2 stays flagged for the owner in 225's open questions.

01
Which hand-pick UI

1 · a numbered list with a search field · 2 · arrange the row itself on a strip with a visible seam · 3 · click tiles in the matches grid to number them.

Lean: 2 · Arrange the row — the seam shows the fallback as a place, not a setting, and the strip is literally what the TV shows. Keep 1's search field inside it for finding a title among hundreds.
02
The default

Date added · newest first (today's behaviour) vs the brief's literal “asc”.

Decided: newest first. The brief's "asc" was a slip.
03
Direction as a toggle or as six options

One key picker + one direction button, or “Title A→Z / Title Z→A / …” spelled out.

Lean: key + direction; the summary line spells the pair out in words (“title A → Z”, “newest release first”), never “asc/desc”.
04
Title sort ignores articles

“The Bear” under B, or under T? Jellyfin already carries SortName; our catalog does not store it.

Lean: read Jellyfin's SortName where it exists (the scanner already fetches the item), fall back to the title. Same answer as the browse page should give.
05
Where a stale hand-pick goes

A pinned title that no longer matches the filter: drop it silently, keep it and skip it on the TV, or block Save.

Lean: keep and skip, marked in the editor — the filter may tighten temporarily, and a pin is deliberate work you shouldn't lose to a side effect.
06
A ceiling on hand-picks

None, or the row cap.

Decided: the row's own length is the ceiling. The viewer sees 10 today, not 30; the number a row shows becomes a per-row setting (Show N titles, 3–30, default 10) and hand-picks can never exceed it — every pin is a tile the viewer can reach.
07
Does See all open in the row's order?

Today R187's page opens on recency regardless. With a row sorted A → Z, See all opening on “newest” means the row and its page disagree on the first tile.

Decided: yes for the automatic key, no for the pins. The row's key becomes the page's initial facet value, the viewer re-sorts as today; hand-picks never reach the page (R253).
08
Hand-picked titles and the 30 cap inside a collection

Pins are resolved against the scoped set, so a row pinned 5-deep on Home may show 3 pins in “Dansk TV”.

Lean: that is correct, say it once in the editor (the collection frame below) and never draw a pin's absence on the TV.
09
Genre rows

RowKind.GENRE is still in the enum.

Decided: they don't exist any more — every non-system row is a workbench filter; only CONTINUE and NEWLY_ADDED are exempt.
10
Config shape

Additive on RowConfig, ignored by any installed TV (it never evaluates rows).

sort: { by: "added" | "title" | "year", descending: true }
pinned: [ "<jellyfinId>", … ] // ordered; empty = no hand-picks

Decided, plus limit: 3..30 (absent = 10). Absent sort reads as added · descending, so every existing row is byte-for-byte the same after the migration.

1 · Pinned list

A numbered list, then the rest by…

Choosing Hand-picked first opens a list. Search to add, drag to reorder, ✕ to release. Beneath it the fallback key and direction. Cheapest to build and the most familiar — but the list and the row look nothing alike, so you are imagining the TV rather than looking at it.
2 · Arrange the row · chosen · built

The strip is the row; the seam is the rule

The Order section shows the row as a horizontal strip. Left of the dashed seam are your hand-picks, numbered; right of it, dimmed, is what the automatic key puts next. Drag a tile across the seam to pin or release it; drag within the left zone to reorder. The seam's label is the fallback control. A search field pins a title you cannot see.
3 · Number the grid

Click a title to give it the next number

No new surface: the matches grid on the right becomes the control. Click a tile → it takes the next number and jumps to the front; click again to release it. Fastest for “put these five first”, worst for “move #4 above #2” — you release and re-number. The unnumbered remainder is dimmed and sorted by the fallback key.

S1 · a hand-pick that no longer matches

Kept in your list, skipped on the TV

Include was switched to Series; Druk is a film. The pin stays where you put it, marked, and the strip says what the TV will do. Nothing is deleted behind your back — loosen the filter and it is back in place.
S2 · the same row inside a collection

Pins outside the collection don't appear there

The Home “Drama” row, inherited into Dansk TV and scoped to it. Trom and Offboarding are pinned on Home but aren't Danish TV, so here the row opens on Fjollerne. One sentence in the editor explains it; the TV shows nothing.
S3 · the row list

The summary line carries the order

In Layout → Content rows each row's second line already says what it filters. It gains the order in words — never “asc/desc” — so you can read the whole stack without opening a row. System rows are unchanged.
