Ravilo · design directions · round 1 · 16 September 2026

The Ravilo player on a phone

Today PlayerScreen renders the TV chrome verbatim on a phone: 48 dp gutters, D-pad pills with focus rings, forced sensor-landscape, no gestures, no safe-area reads. Three directions follow, differing on one axis only — where the secondary controls live — because that is what decides whether it can be used with one thumb.

What is fixed before any direction

  • 46 px targets, 13 px type floor — the phone mockup's own rules (R234). The skip buttons therefore read 10 s / 30 s as labels beneath the arrow, never as an 11 px numeral inside it.
  • Nothing names the delivery method (R180 FR-RV-ASP1-2). No "transcoding", no codec, no bitrate, anywhere a viewer can read it.
  • Waiting states reuse R218 — cold start is pulse + title + sweep + "Loading…"; a stall raises the chrome and puts the spinner in the play button's place; a seek spins inside the scrub bubble.
  • Failure reuses R237 — nine causes × en/da/fo, no product, protocol or status code. On a phone it becomes a sheet with Try again / Back.
  • The picker is R180/R195 — same two levels, same flags, same version badges, as a bottom sheet. The only addition is Subtitle size.
  • Foreground only — owner decision: no background audio, no PiP, no local mini-player.

What I did not draw, deliberately

  • Thumbnail scrub previews. trickplayUrl is null on every ticket — there is nothing to render, and a blank tile is worse than no tile.
  • Any AirPlay affordance. Dropped outright, 16 September 2026.
  • Lock-screen or notification controls for local playback. R193 stands: the phone never creates an OS-level media session. The casting notification is a different thing and lives in the casting document.
  • Home, Detail, Browse, Search, Discover, Live TV guide, login. Brief §D — the second round, which waits on the picks from this one.
  • Tablets. Every frame is a handset.
Artwork is a stand-in. Only Big Buck Bunny has real artwork in this project, so every still is its backdrop under a series' title — the substitution artFor() already makes. Judge layout and type, not the picture.

Auto-hide

The TV's 3 600 ms is right for a remote you put down. On a phone the chrome is summoned by the same tap that could be a mis-tap, so 3 000 ms is the proposal, with two exceptions that hold it open — a sheet is open, or a drag is in progress. Nothing auto-hides while Locked.

Consequence

The one gap that is a backend fact, not a UI choice

A phone on cellular gets no bitrate cap at all.

Phase 177 and R216 give the server two inputs for MaxStreamingBitrate: the device's own decoder ceiling, and a link-derived cap from detectLinkState(). That detector handles ethernet and Wi-Fi and returns UNKNOWN for everything else — including cellular. ClientCapabilities.linkKind = "unknown" means, by its own documentation, that phase 177's link-derived cap never applies.

So a phone on LTE direct-plays a 93 Mbps remux exactly as the stue TV did before phase 177 — with the extra cost that it is someone's data plan. R183 already established that a VideoBitrate condition disqualifies direct play, so the correct knob is MaxStreamingBitrate on PlaybackInfo, fed by a viewer-facing quality setting rather than a link guess.

This is the cheapest real win on the whole list and it is not a player change: one Settings row (Quality on mobile data — Auto · Data saver · Always high) and a Wi-Fi only switch. It is out of this canvas because it belongs on the Settings screen — say the word and it is drawn.

Where the build would land, after the picks

  • Player chrome, sheets and gestures → Ravilo Mobile.html and mobile/ravilo-mobile.css, behind the same LocalHandset-shaped switch the code uses, so the TV mockups stay untouched.
  • The iPhone frame is already in Ravilo Mobile.html — a device picker beneath the phone swaps the Pixel 9 bezel for an iPhone 16 with a Dynamic Island and home indicator, and every existing screen renders in both. ?dev=ios works too.
  • Nothing else in that file was touched, per the brief.

Numbering, for information only

The research report proposes phase numbers against 216 / R243. Those were taken the same day by the Discover taxonomy pair, and 217 by the Towo removal. Verified against main today: admin runs to 217, Ravilo to R243, so the next free pair is 218 / R244 and the whole proposed ladder shifts by one. No spec is written or edited by this round.
