Subtitles — telling apart tracks that share a language

R180's flag-forward picker assumes one row per language reads as one choice. In this library it usually doesn't: almost half of all movies and series carry a file where the same language appears on two or more subtitle tracks — plain vs. SDH, forced, dialects, dub-titles, commentary, release-provenance duplicates, and in the worst case whole sets of unnamed image subtitles. Three directions below, each shown on a title that exercises the real cases, plus how each survives the library's hardest file. Shared vocabulary and the underlying data fixes are at the bottom.

What has to change underneath, whichever direction wins

SDH becomes a real, detected badge

It is the single most common variant (1,300+ raw “SDH” title occurrences) and today nothing sets it. Detect from title text SDH / HI / hearing and from Bazarr's own hi flag — the picker keeps the shipped word Sound described.

A region synonym table, not string matching

Castilian, Spanish (Spain) → 🇪🇸; Latin American, Latin America → a neutral globe; Brazilian → 🇧🇷; Simplified/Traditional → 🇨🇳/🇹🇼. Unconfident match falls back to the plain language flag — never a wrong flag.

Provenance is noise — suppress it

BluRay / iTunes / WEB-DL variants of the same language and kind are one viewer choice. Merge them into a single row (keep the best-scoring file) rather than offering a release name as if it were a decision.

Remember the version, not the language

RememberedChoice stores only a language today, so a viewer who always picks SDH gets whatever track sits first in stream order next time. It must store the resolved variant signature — a prerequisite for any of these designs to feel trustworthy.

Open question for the spec: R180's “nothing hidden or merged” invariant is directly in tension with the provenance merge and with A's second screen. Recommendation — keep it for tracks a viewer could meaningfully choose between, and let it yield where the difference is release plumbing rather than content.
