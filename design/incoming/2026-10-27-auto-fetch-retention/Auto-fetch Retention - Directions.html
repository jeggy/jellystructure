What is fixed

These came with the brief and the round designs inside them. None of them was a choice to make here.

  • The frontend renders server-pushed state only. So the deletes 4 episodes count is the server's preview (FR-12's route), and the screen never works it out. In these pictures that is one retention function in af-keep-data.js, standing in for the server, so the count in the preview and the deletion in the run record cannot disagree.
  • A control that cannot do anything is shown disabled, with its reason (processing-runs-as-nine-features.md FR-11).
  • The tick, verbatim: This programme is not on TMDB. A blank id without it is refused: Auto-fetch needs a TMDB id, or tick “not on TMDB” (FR-15.1).
  • Ticked, the id field is disabled and empty, and its hint reads The episodes keep the page's own titles and descriptions, and nothing asks TMDB. The series only badge stays (FR-10.6).
  • The page-only review state: Dagbók · page only · not on TMDB; the proof line 12 items, each with its own date; Becomes showing S2026E300 · 2026-10-27; the echo carrying the page's own name and image (FR-10.6).
  • Keep: All episodes or The newest N (1 to 999, 12 when first shown), with Also delete an episode once it leaves the page shown only with The newest; between Check for new episodes and Run the first time; hint Keeps 12 of the 12 on the page. Older ones are deleted from the library. A page-only fetcher starts at The newest 12 with the tick on; a TMDB fetcher starts at All episodes (FR-16.1).
  • The open row shows the same control, editable in place, and Saving this deletes 4 episodes at the next run before saving (FR-10.6).
  • The run lines as FR-16.6 words them, the Activity entry as FR-11 words it, and the list row's Daily · 04:00 · keeps newest 12.
  • No notification, no toast, no confirm dialog. The preview line is the warning (FR-16.7).

One direction, and why there is only one

This is an addendum, not a pick-a-direction round. The brief fixes the words, the places and the defaults; what was left to draw was the shape of one new control and the behaviour of the shipped components around it. Where a shape was genuinely open, the choice is named below with what it costs. Where the picture disagrees with the brief, that is a finding and it is in REPORT.md, not quietly resolved here.

The Keep control: the number lives inside its option

The settings box on the review state is 300 px wide, which is 270 px of content. A segmented control plus a separate number field does not fit on one line at that width, and stacking them turns one setting into two. So the number sits inside the option it belongs to — The newest 12 — which is how the spec itself writes it.

  • With All episodes chosen, the number is still drawn, as dimmed text at the same width. Nothing moves when the option is chosen, and the default is readable before it is.
  • It is not a control shown disabled with a reason (FR-11): it is the other option's own value. The seg beside it is the reason, and there is no sentence a disabled-field reason could add that the two words All episodes do not already say.
  • The cost: a reader who wants to change only the number has to notice it is live only on the chosen side. The alternative costs a wrapped two-line control in the box it has to live in.

The tick: the shipped tick glyph, with a sentence beside it

wf.css has a .toggle for a setting that acts the moment it is pressed, and nothing for one that is saved with a form. .af-tick is already the shipped tick — it is what a mapping row's accept tick draws — so .af-opt is only the label around it. Both of this round's ticks use it, so This programme is not on TMDB and Also delete an episode once it leaves the page are the same mark, which is right: both are things the admin is choosing, not switches that do something as they are pressed.

The preview: a warn band under the control, never a dialog

FR-16.7 is explicit that the line is the warning. So it is warn-tinted, it carries a mark, and it sits directly under the control that caused it with Save beside it — the change, the consequence and the consent in one column, in that order.

A deletion is a line under the run, not a run of its own

A run's line keeps its summary — +1 episode · −1 by retention, which is word for word what FR-11 gives the Activity entry — and each placement, deletion and guard is a line indented under it. The run and its lines are one record and the rule between runs moves to the group. One set of words, two places.

Open questions

1 · Does FR-10.6's Keep hint belong on the review state as it stands? Its second sentence — Older ones are deleted from the library — is a statement about future runs, and on a review state the fetcher has placed nothing, so nothing can be deleted when it is saved (FR-16.2). The fixed string is drawn unaltered and a second line beneath it says so. Either that line stays, or FR-10.6 gains FR-16.4's words for the review state and keeps the fixed string for the open row.
2 · On a TMDB fetcher that chooses The newest, is leaves the page on or off by default? FR-16.1 fixes the default for a page-only fetcher and for a TMDB fetcher's All episodes, but not this. Drawn off, for the reason in the decided rows.
3 · Does a list row need to say page only? Drawn without: the Numbering cell carries Date · S{year}E{day of year}, which no TMDB fetcher can show, and the open row's footer says page only, no TMDB id where a TMDB fetcher links its id. A badge flat beside the name is the alternative and costs one more thing on every row.
4 · Activity ▸ History has no drawn entry for a fetcher. activity.html is the scan console. FR-11's entry needs a surface, and inventing one here would be drawing a screen nobody briefed. Is that a round of its own, or does the build take the words and put them in whatever History already renders?
5 · Should the preview name the four episodes, not only count them? FR-12's route returns what saving that retention would delete, so the server could hand over the codes. Drawn as the count alone because that is the sentence the spec fixes.
