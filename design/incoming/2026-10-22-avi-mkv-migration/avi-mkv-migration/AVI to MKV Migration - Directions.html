Turning a failed AVI language edit into a deliberate MKV conversion

An audio-language edit on an AVI can't be made to stick, because AVI has no field for it. This round asks where the step from that failure to a container conversion lives — in the row that failed, or on the file — and how the operator sees it blocked, running, verified or failed. Three named directions follow. Direction A draws the brief's leans in full; B and C are sketches of the two alternatives. Nothing here is decided.

What is fixed

  • “Identify tracks with no language tag → surface them in Triage for manual correction.” — Audio 1 carries the Triage badge until a re-probe finds a tag.
  • “Track default flags and ordering are never changed automatically.” — the ★ and the order are never touched by any frame.
  • “Choose the least destructive tool sufficient for the operation.” A container change is a stream-copy remux: Video and audio are copied without re-encoding.
  • Working files go into a hidden .jellystructure folder in the same directory, so the final move into place is one atomic rename.
  • A file hard-linked to a torrent still seeding is Blocked; an unreachable safety check is also blocked — unknown means no.
  • The migration is explicit and operator-initiated. Saving a language never converts as a side effect.
  • A zero exit code is not success. Success appears only after the re-probe confirms the tag; a clean exit with no tag is a failure.
  • The original stays available until the result is verified. No frame implies the AVI is gone.
  • The app doesn't repair filenames. The basename is shown and editable; nothing is renamed silently.
  • Other devices aren't instantly current. They change only once the media server has indexed the result.
  • No frame tells the operator to run a command, or shows one.

Three named directions

They differ in where the conversion lives and whether it can be reached without a failure first. They share the same preview, confirmation, job states and wording, so the comparison stays about placement.

Lean · drawn in full · slug file-action

A · File action, reached from the failed row

The row says “Not kept” and links to a file-level notice above the Tracks card. The notice explains the AVI limit and offers the conversion in the same breath. The preview, the confirmation and the job's whole life stay on that file card. The row only locks and points up.

Why it reads right: a container change rewrites every stream, not just Audio 1, so the control sits at the scope it acts on. The operator still reaches it only by way of the failure (D5 lean).

Alternative to D1 · sketch · slug in-row

B · Migration inside the track row

The failed row opens a drawer. The explanation, the offer, a compact confirmation and the progress all live inside Audio 1.

It's the shortest path, and the eye never leaves the row. The cost: a whole-file action reads as a one-track action. With several untagged tracks the offer repeats, or appears on only one row. At 390 px the drawer is cramped.

Alternative to D5 · sketch · slug standing

C · Standing container action

A file card always shows AVI with a Convert to MKV… action, whether or not an edit has failed. A failed edit highlights that card.

It's discoverable, and it would let an operator migrate ahead of tagging. The cost: the action is reachable without the explanation that justifies it, and a permanent button on every AVI invites conversions nobody needed.
