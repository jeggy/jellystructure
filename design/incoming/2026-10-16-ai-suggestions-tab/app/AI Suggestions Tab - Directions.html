Round · ai-suggestions-tab · no phase number

Suggestions as the third tab of the AI page

The question: when an AI key is set, how does today’s full Suggestions page sit as the third tab of the AI page, and what does it give up to fit under a header it no longer owns? Admin only, at the desktop width (1280) and the admin’s narrow breakpoint (390). Two named directions, the recommended one carried through every state, then the three open decisions with their alternatives drawn, then the strings. Read left to right, top to bottom.

What is fixed — drawn as given, not reopened

  • The owner, verbatim: if AI key is there, then it’s under the AI page, otherwise it stays as is. Only the first case is drawn: key set and Seerr connected ⇒ Suggestions is a tab on the AI page and there is no Suggestions entry in the sidebar. No key ⇒ today’s page, unchanged, not drawn. No Seerr ⇒ Suggestions is nowhere.
  • Tab order: Support · Fetchers · Suggestions. Support needs support on and a key; Fetchers needs a key; Suggestions needs Seerr. The AI page exists only while a key is set.
  • One shell. The tab switcher (tk-tabs, Support 2 · Fetchers), the header row (AI · API key valid · model reachable · Key & model → Settings) and their narrow breakpoint are extended, not redrawn.
  • Absent, never greyed. A tab whose feature is off is not drawn — no disabled tab, no empty-state tab, no explanation.
  • Server-pushed state only: The frontend renders server-pushed state only — no derived or optimistic local state. Every number drawn is one the server sent.
  • Tabs use replaceState: Back/Forward navigate between pages, not between tabs. Deep-linking and refresh still reconstruct the correct tab from the URL.
  • Type and colour: Space Grotesk · Sora · JetBrains Mono; --ok / --warn / --bad. Dark-primary with a light toggle — the recommended direction is drawn in both.
  • The Suggestions content does not change. Suggestions · Seerr connected · Built {when} · {n} shown of 50 · Dismissed ({n}) · Rebuild now; Built from {n} finished films:; the cluster-source line; the cluster groups with Download and No thanks; Show more; the Dismissed view; the Seerr couldn’t be reached banner. Only where it sits is drawn — except Show more, which the owner moved under each group on 2026-10-16 (section 2).
How the tension is held. The shared header stays the AI page’s and never changes with the tab. Everything Suggestions used to put in its own title row moves, word for word, into a toolbar row that belongs to the tab panel — so switching tabs toggles only the panel, as the contract says. What the page gives up is listed beside the comparison in section 1: its title, its sidebar entry, its place as a landing page, and one click.

What Suggestions gives up by moving — both directions

  • Its title. The Suggestions heading survives only as the tab label; the page’s h1 is AI.
  • Its sidebar entry between Library and Activity. Reaching it is now AI → Suggestions: one more click, and the AI page opens on its first present tab (Support), never on Suggestions unless the link says ?tab=suggestions.
  • Its address. suggestions.html becomes the no-key page only. With a key set, a link to it — the Dashboard card’s included — must land on ai.html?tab=suggestions. Not drawn; reported.
  • A header to itself. The connection badge no longer sits beside a title of its own; in A it leads the toolbar, in B it shares a row with the AI’s badge.
  • Nothing of its content. Every line, control and behaviour listed in FIXED is drawn unchanged.

3 · The three decisions — decided by the owner, 2026-10-16the lean of each was picked and is drawn above; the alternative stays here for the record
Decision 1

Where do Suggestions’ own header controls go?

Decided

A toolbar row under the tabs

Direction A. The AI header keeps its title, badge and Key & model → Settings; the tab’s row carries Seerr connected · Built · shown · Dismissed · Rebuild now.

Not picked

Up into the shared header

Direction B, section 1. Wraps the header at 1280 and to five lines at 390, and makes the header change with the tab.

Decided: the toolbar. B’s header changes on every tab switch, which the shipped contract rules out (Only the tab panel toggles in the DOM). A costs one toolbar row and nothing else.
Decision 2

Where does Dismissed open?

Decided

Inside the tab, replacing the list

Section 2, state 4. Close returns to the list. ?tab=suggestions&view=dismissed by replaceState.

Not picked

A drawer beside the list

To the right. 470px from the right edge over a scrim at 1280; at 390 it can only be a full-screen layer with ✕ Close.

Decided: inside the tab. It is the one that survives replaceState without Back. Both can be written to the URL the same way, and both close with their own button. But the drawer is an overlay: at 390 it covers the whole page, and a full-screen layer is the one thing an admin closes with Back by reflex — and Back, by the contract, leaves the AI page altogether. The in-tab view is a state of the panel, not a layer above it, so nobody reaches for Back to leave it. The drawer’s one gain, the list visible beside it, exists only at desktop and only behind a scrim.
Not picked · drawer · desktop 1280
Not picked · drawer · narrow 390
Decision 3

Does the sidebar’s AI entry carry a second number?

Decided

Unchanged: the open-ticket count only

AI 2. Suggestions adds no count. With the key set, the Suggestions entry is simply gone from between Library and Activity.

Not picked

A second, neutral count

AI 2 3: the red ticket count, then a grey count of suggestions new since the admin last looked — the server already sends this figure (newSince: 3). The tab label carries the same 3.

Decided: the open-ticket count only. The red count means “someone is waiting for you”; three new films are not waiting for anyone. Two numbers on one entry cannot be told apart without hovering, and when support is off the entry would carry only the grey one, which reads like a ticket count with the wrong colour.
